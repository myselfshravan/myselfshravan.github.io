One command to run, one commit to ship

Local: docker compose up --build brings up the API and worker against a single Postgres. No Redis, no SQS: Procrastinate uses the same Postgres as its queue. One-time DB setup is three commands. Production: one Docker image, two entrypoints (ops-api, ops-worker) on AWS ECS Fargate, fully defined in 13 Terraform files (ECS, ALB, ECR, CloudFront, IAM, Secrets). Deploys are commit-message-driven in CI: put #deploy-api, #deploy-worker or #deploy in the merge and it builds, pushes to ECR, and rolls the service.

Operate from a console, not a shell. A FastAPI control plane exposes 37 endpoints: trigger and watch crawls, browse the catalog and quality metrics, inspect the queue, prune dead-letters, sync the vector index, all behind JWT + RBAC. Crawls are idempotent and resumable (per-source checkpoints), locked one-per-brand, and reaped automatically if a worker dies. Adding a brand is config-only on a shared toolkit (~20 lines); bespoke platforms get a self-contained package that never touches core.

The moat: a contract-first seam

Core owns the streaming pipeline, stores, normalization and the universal schema. Each brand is a self-contained package implementing three duck-typed protocols Descriptor / Scraper / Transformer. Core never switches on brand names, so a new Shopify brand is config while a bespoke platform is a full package that never touches core. That seam is what lets the system reach 120 brands without collapsing into one-off scripts.

Idempotent & resumable long crawls checkpoint every batch and survive a mid-run DB blip. Replayable raw payloads are stored, so a parser improvement re-enriches the catalog with no re-crawl (this is how material coverage went 0% → ~99%). Stale-row reconciliation delists anything not re-seen, so no zombie listings. The ops plane runs on FastAPI + a Postgres-backed queue no Redis, no SQS.

07 · Diligence notes

Honest caveats, so the pitch holds up

  • Provenance of the numbers. The headline quantum (963.6K styles · 907.1K products · 4.9M SKUs · 114 sources) is the catalog this codebase produced in its deployed crawl run. The field-coverage percentages and the price detail counts are from the last full DB audit (a 23 to 24 brand cohort): the quality bar the pipeline holds as brands load. The queries in docs/CATALOG-METRICS.md reproduce every figure against a fresh Postgres at diligence.
  • Crawl cadence is operator-set. Periodic housekeeping (stalled-job reaper, stale-run reconcile, sync sweep) ships wired on a cron; per-brand full-crawl schedules are added by the operator via Procrastinate's @app.periodic. The plumbing is in, the cadence is yours to choose.
  • Price history depth is days, not months. Integrity + cadence are the flex: run it daily and the series extends itself.
  • Not an anti-bot evasion engine, by design. Sites requiring sustained headless evasion are out of scope; the covered surface is the ten-platform library above.
  • Source-limited attribute gaps are category-correct. A few brands under-list fit or neckline at source e.g. neckline on trousers which are correct nulls, not pipeline failures.
